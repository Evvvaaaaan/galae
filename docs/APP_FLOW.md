# 갈래 화면과 사용자 흐름

2026-11-05 기준. 현재 프론트엔드 코드를 기준으로 한 화면·경로·규칙·저장 명세입니다. 기획 의도는 [PURPOSE.md](PURPOSE.md), 설계는 [PLAN.md](PLAN.md), 세계수와 업적은 [ACHIEVEMENTS.md](ACHIEVEMENTS.md)를 봅니다.

## 1. 디자인 원칙

- 흰 배경, 푸른 선, 명조 제목. 갈래 선 모티프를 쓴다.
- 설명 문구, 라벨, 배지, 안내 각주를 두지 않는다. 텍스트는 콘텐츠와 꼭 필요한 버튼만 둔다.
- 버튼은 `#EAF2F9` 배경에 `#2B4A63` 글자.

## 2. 흐름

```
시작 → 가입 → 온보딩 4장 → 오늘
시작 → 로그인 → 오늘
선택 → 결과(→ 선택지 코멘트) → 확장하기 → 완료(→ 공유 시트)
끝낸 질문을 다시 열면 → 요약
```

답변 중에도 하단 탭은 유지됩니다. 탭을 바꿔도 초안이 남고, 뒤로가기·앞으로가기·새로고침으로 현재 화면을 다시 열 수 있습니다.

## 3. 탭

| 탭 | 경로 | 역할 | 상단 |
| --- | --- | --- | --- |
| 오늘 | `#/today` | 세계수, 출석, 오늘의 질문, 그룹 | 로고 |
| 생각 | `#/feed` | 철학 역설 피드 | 제목 |
| 질문 | `#/archive` | 질문 모아보기 | 제목 |
| 그룹 | `#/groups` | 그룹 나눔 | 제목, + 메뉴(만들기·참여) |
| 나 | `#/records` | 프로필, 열매, 달력 | 제목, 설정 |

## 4. 화면

| 화면 | 경로 | 보이는 것 |
| --- | --- | --- |
| 시작 | 첫 방문 | 선 모티프, 갈래, 한 줄 소개, 시작하기, 로그인 |
| 가입 | 시작하기 | 아이디(영문 소문자·숫자·`.`·`_`, 20자), 비밀번호(8자 이상), 이름(10자) |
| 로그인 | 로그인 | 아이디, 비밀번호 |
| 온보딩 | 가입 후 | 4장(오늘의 질문, 먼저 답하기, 생각 탭, 나무), 건너뛰기 |
| 오늘 | `#/today` | 세계수 → 이번 주 출석(연속 일수) → 질문 카드(날짜, 질문, 참여 수, 버튼) → 가입 그룹 2개(오늘 나눈 멤버) |
| 생각 | `#/feed`, `#/feed/:topicId` | 위아래로 넘기는 주제. 한 화면에 제목, 글, 출처, 댓글·공유. 하루 5개 뒤에 끝 화면 |
| 생각 댓글 | 생각의 댓글 버튼 | 아래에서 올라오는 시트. 답글, 공감, 아이디 표시. 위로 끌면 전체 화면 |
| 질문 | `#/archive` | 검색, 상태 필터(전체·미답변·답변 완료), 질문 목록 |
| 선택 | `#/question/:id/answer` | 진행 선, 질문, 선택지, 이유(선택 입력·500자), 선택하기 |
| 결과 | `#/question/:id/result` | 선택별 비율 막대. 내 선택은 색으로만 구분. 비율 옆 화살표로 코멘트 보기 |
| 선택지 코멘트 | `#/question/:id/result/:choiceId` | 질문 카드(질문, 그 선택지와 비율), 아래에 댓글. 내가 고른 선택지면 내 이유가 맨 위 |
| 확장하기 | `#/question/:id/reading` | 관점별 해설(성경·철학·오늘의 연구). 성경은 구절과 장절. 성경 외 관점은 자리 표시용 |
| 완료 | `#/question/:id/done` | 질문, 내 선택, 공유하기, 홈으로 |
| 요약 | `#/question/:id/summary` | 끝낸 질문을 다시 열면 나옴. 질문, 내 선택과 이유, 비율, 공유 중인 그룹, 확장하기 다시 확인, 공유하기, 홈으로, 다시 하기 |
| 공유 시트 | 완료·요약 위에 열림(경로 없음) | 그룹 복수 선택, 저장, 외부 공유. 저장하면 닫힘 |
| 그룹 | `#/groups` | 가입 그룹 목록(소개, 멤버 수) |
| 그룹 만들기 | `#/groups/new` | 색, 이름(20자), 소개(100자). 만든 뒤 멤버 화면 |
| 그룹 참여 | `#/groups/join` | 6자리 초대 코드. 잘못된 코드·중복 가입 처리 |
| 그룹 대화 | `#/groups/:id(/:questionId)` | 질문 선택, 질문 카드, 그룹원의 선택과 이유, 메시지 입력. 답하기 전에는 그룹원 글이 흐리게 보이고 답하기 버튼이 있음 |
| 멤버 | `#/groups/:id/members` | 초대 코드·복사, 멤버, 그룹장은 내보내기·그룹 설정, 나가기(한 번 더 확인) |
| 그룹 설정 | `#/groups/:id/settings` | 그룹장만. 색, 이름, 소개 수정 |
| 나 | `#/records` | 프로필(이름, 선택·연속·댓글 수, 소개), 프로필 편집, 열매 줄, 달력, 고른 날의 답변 |
| 내 댓글 | `#/records/comments` | 생각에 남긴 댓글. 누르면 그 주제로 |
| 다른 사람 프로필 | `#/users/:id` | 이름, 숫자, 소개, 열매, 그 사람의 나무 |
| 설정 | `#/settings` | 프로필, 로그아웃, 갈래 소개(온보딩 다시 보기), 출처, 기록 초기화. 알림·계정 연결·탈퇴·약관 등은 비활성 |
| 프로필 편집 | `#/settings/profile` | 사진(256px로 줄여 저장), 색, 이름(10자), 아이디, 소개(80자) |
| 출처 | `#/settings/sources` | 성경 역본과 생각 피드의 출처 |
| 찾을 수 없음 | 없는 경로, 나간 그룹 | 안내와 오늘로 |

## 5. 답변과 공유 규칙

1. 질문별 상태를 따로 저장합니다. 한 질문의 초안이 다른 질문에 나타나지 않습니다.
2. 선택하지 않으면 제출할 수 없습니다. 이유는 선택 사항이며 500자 이내입니다. 제출한 선택과 이유는 읽기 전용입니다.
3. 아직 제출하지 않은 질문은 결과 경로로 직접 들어와도 선택 화면이 열립니다. 확장하기를 마치기 전에 완료·요약 경로로 들어오면 확장하기가 열립니다.
4. 확장하기에서 다음을 누르면 완료 처리됩니다.
5. 미완료 질문은 마지막으로 보던 단계에서 이어집니다. 끝낸 질문은 요약 화면으로 열립니다. 요약의 다시 하기는 선택부터 확장하기까지 새로 답하는 흐름을 그대로 따릅니다. 선택하기를 누르면 선택과 이유만 바뀌고, 처음 답한 날·완료 같은 나머지 기록은 그대로입니다. 이미 보낸 공유 메시지도 그대로라서 바뀐 답은 아직 아무 그룹에도 보내지 않은 상태가 됩니다. 선택과 이유가 이전과 같으면 아무것도 바뀌지 않습니다. 선택하기 전에 그만두면 원래 답이 남습니다.
6. 다른 사람의 답변을 보려고 내 답변을 공유할 필요는 없습니다. 그룹에 가입해도 기존 답변은 공유되지 않습니다.
7. 공유 시트에서 그룹을 고르고 공유하면 그 그룹 대화에 지금 답(선택과 이유)이 메시지 한 건으로 올라갑니다. 고른 그룹은 질문별 초안으로 남지만, 보내기 전에는 그룹에 보이지 않습니다. 그룹 대화에서 들어온 질문이면 공유 시트에 그 그룹이 미리 선택됩니다. 그룹을 고르지 않고 나만 보기로 저장하면 아무 그룹에도 보내지 않습니다.
8. 보낸 공유 메시지는 일반 메시지처럼 수정하거나 거둘 수 없습니다. 공유 시트에서 지금 답을 이미 보낸 그룹은 체크된 채 풀 수 없고, 완료·요약의 공유 표시도 지금 답을 보낸 그룹만 셉니다.
9. 그룹을 나가면 그 그룹 초안과 그 그룹에 보낸 메시지(공유 포함)가 지워지고 개인 기록은 남습니다. 그룹장이 나가면 그룹이 사라집니다.
10. 그룹 대화에서 질문을 바꾸면 주소도 바뀌어 새로고침·앞뒤 이동으로 복원됩니다.
11. 달력에서 색칠된 날은 답한 날(`answeredOn`)입니다. 가입한 날부터 오늘까지만 누를 수 있습니다.
12. 연속 일수는 오늘(아직 안 답했으면 어제)부터 거슬러 올라가며 하루도 빠짐없이 답한 날 수입니다.

## 7. 서버 연동 이후의 경계

가입·로그인은 화면만 있고 비밀번호를 확인하거나 저장하지 않습니다. 실제 인증, 사용자별 데이터, 그룹 초대·권한·탈퇴, 공유 접근 제어, 실제 참여 통계, 날짜별 콘텐츠 공급, AI 해설 생성은 서버에서 처리해야 합니다. 결과 잠금과 그룹 필터는 화면 동작일 뿐 보안 경계가 아닙니다. 참여 수, 비율, 다른 사람의 의견·나눔·댓글은 예시 데이터입니다.

그룹 공유는 그룹 메시지 한 건입니다(`{ groupId, questionId, sel, text }`, 일반 메시지는 `sel`이 없음). 서버도 같은 모양으로 메시지 테이블에 저장하면 됩니다. 다시 하기로 답을 바꿔도 이미 보낸 메시지는 바뀌지 않고, 새 답은 다시 공유해야 새 메시지로 올라갑니다.
