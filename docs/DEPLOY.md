# 배포 방안

공모전 제출까지 앱 스토어 심사를 마치기 어려워서, 포트폴리오 사이트에 앱 형식으로 배포하는 방안을 정리합니다.

## 현재 상태

- React와 Vite만 쓰는 순수 정적 웹앱이며, 서버나 DB가 없다.
- 데이터는 브라우저의 `localStorage`에만 저장한다.
- 라우터 라이브러리가 없어서, 새로고침할 때 404가 나는 문제를 신경 쓸 필요가 없다.
- `npm run build`로 만든 `dist/` 폴더를 올리면 배포된다.

## 배포 전 확인할 것

1. **올릴 주소**
   - `galae.도메인.com`처럼 서브도메인에 올리면 설정을 바꿀 필요가 없다.
   - `도메인.com/galae`처럼 하위 경로에 올리면 `vite.config.js`에 `base: '/galae/'`를 추가해야 한다. 없으면 JS와 CSS 경로가 깨진다.
2. **배포 버전에 보이는 역설 카드**: `src/screens/Feed.jsx`에서 배포 빌드는 `checked: true`인 카드만 보여 준다. 제출 전에 검수 상태를 확인한다.
3. **모바일 화면**: 심사위원은 주로 휴대폰으로 볼 것이므로, 휴대폰 브라우저에서 화면을 직접 확인한다.

## 서버 연결

프론트엔드는 포트폴리오 사이트에 올리고, 서버는 따로 띄운다.

### 챙길 것

1. **HTTPS**: 포트폴리오가 https라면 서버도 https여야 요청이 막히지 않는다.
2. **CORS**: 서버 주소가 포트폴리오 도메인과 다르면, 서버에서 포트폴리오 도메인의 요청을 허용한다.
3. **서버 주소 설정**: `.env`에 `VITE_API_URL` 같은 값으로 분리해서, 개발용과 배포용 주소를 나눠 쓴다.
4. **무료 서버의 대기 상태**: 무료 호스팅은 한동안 요청이 없으면 서버가 잠든다. 처음 열 때 수십 초씩 걸릴 수 있으니 심사 기간에는 주의한다.

### 선택지

- **같은 곳에서 서버리스 함수 쓰기**: 포트폴리오가 Vercel이나 Cloudflare Pages에 있다면, 같은 프로젝트 안에 API를 넣는다. 도메인이 같아서 CORS 문제가 없고, 관리할 곳도 한 군데다.
- **서버를 따로 두기**: Render, Railway, Fly.io, Supabase 같은 곳에 띄우고 프론트엔드에서 호출한다.

## 앱 형식으로 배포하기: PWA

스토어 심사 없이 포트폴리오 주소에서 바로 설치할 수 있다.

### 할 수 있는 것

- 홈 화면에 앱 아이콘이 생기고, 실행하면 주소창 없이 전체 화면으로 열린다.
- 서버 연결은 일반 웹과 똑같이 된다.
- 수정한 내용을 배포하면 바로 반영되고, 다시 심사받을 필요가 없다.

### 필요한 작업

1. `manifest.webmanifest`에 앱 이름, 아이콘, 테마 색, `display: standalone`을 지정한다.
2. 아이콘을 192px과 512px로 만들고, iOS용 `apple-touch-icon`도 준비한다.
3. `index.html`에 iOS용 메타 태그를 추가한다.
4. 오프라인 실행이 필요하다면 서비스 워커를 추가한다. 서버를 쓴다면 처음엔 빼도 된다.

### 한계

- iOS는 설치 버튼이 따로 뜨지 않는다. 사파리에서 공유 → "홈 화면에 추가"를 직접 눌러야 하므로 심사위원용 안내가 필요할 수 있다.
- 앱 스토어 링크로 내려받는 방식은 아니다.

## 실제 앱 파일이 필요한 경우

- **안드로이드**: Capacitor로 감싼 APK를 포트폴리오에서 직접 내려받게 한다. 심사가 없다.
- **iOS**: TestFlight 외부 테스트를 쓴다. 베타 심사를 거치지만 보통 하루 안팎이라 정식 심사보다 훨씬 빠르다.
